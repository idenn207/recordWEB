# 웹 목업: 파일 관리, 녹화 현황

`PATTERNS.md`(동작 기준)와 `DESIGN.md`(시각 기준)를 따라 만든 정적 HTML 목업입니다. 프로덕션 코드가 아니고 API에 연결되어 있지 않습니다.
색, 간격, 아이콘 경로는 `apps/web/src/app/styles/index.css`, `shared/ui/icon.tsx`와 같습니다. 새 시각 방향은 만들지 않았고, 현재 구현에 없는 패턴만 채웠습니다.

## 보는 법

```bash
cd docs/mockups
python -m http.server 8765      # ES 모듈이라 file:// 로는 열리지 않습니다
```

- `http://localhost:8765/files.html` 위쪽 도구 줄에서 상태를 바꿉니다(주소의 `#상태`로 공유 가능). 테마 버튼으로 밝음/어두움을 바꿉니다.
- `http://localhost:8765/dashboard.html` 도 같은 방식입니다.
- 각 화면 맨 아래 "열린 결정"을 펼치면 그 상태가 기대는 `[가정]`, `[미결]` 항목이 나옵니다.

| 화면 | 상태 |
|---|---|
| files.html | 기본, 일괄 선택, 일부 실패, 불러오는 중, 빈 폴더, 검색 결과 없음, 불러오기 오류, 삭제(휴지통), 삭제(입력 확인) |
| dashboard.html | 기본, 연결 끊김(데이터 유지), 전체 중지 확인, 전체 시작 일부 실패, 불러오는 중, 채널 없음 |

## 현재 구현과 PATTERNS.md의 차이 (코드를 읽고 비교한 결과)

React 앱을 실행해서 잰 값이 아니라 `apps/web` 소스를 읽고 비교한 결과입니다.

| 번호 | 위치 | 현재 | 기준 | 목업 |
|---|---|---|---|---|
| 1 | `file-dialogs.tsx` DeleteDialog | 폴더, 다수, 완전 삭제도 같은 대화상자. 입력 확인 없음 | §1 영향도별 확인 강도 | 삭제 · 입력 확인 |
| 2 | `file-explorer.tsx` 행 메뉴 | 일괄 선택 중에도 행 메뉴가 살아 있음 | §2 일괄 모드에서 행 액션 비활성화 | 일괄 선택 |
| 3 | 일괄 작업 바 | "N개 선택"만 표시. 사용 중 파일이 섞이면 버튼만 꺼지고 이유는 없음 | §2 선택 개수와 이유 | 일괄 선택 |
| 4 | `doUpload`, `doStreamCopy` | 토스트에 실패 개수와 첫 오류만 표시. 어떤 파일이 왜 실패했는지 모름 | §2 일부 실패 [미결] | 일부 실패 |
| 5 | 검색 결과 없음 | 제목만 있고 필터 해제 동작과 개수가 없음 | §4 | 검색 결과 없음 |
| 6 | 빈 폴더 | 제목만 있고 다음 행동이 없음 | §4 | 빈 폴더 |
| 7 | 불러오는 중 | `불러오는 중…` 텍스트만 | operate.md 스켈레톤 | 불러오는 중 |
| 8 | 경로, 정렬, 검색 | React state. 새로고침하면 사라지고 링크로 공유 불가 | §3 URL이 유일한 기준 | 목업에 없음(동작) |
| 9 | 헤더 체크박스 | 일부 선택 표시(indeterminate) 없음 | 접근성 | 일괄 선택 |
| 10 | 디스크 | 파일 관리 칩은 90%만 강조, 대시보드 막대는 80/90. 사용량 출처 표기 없음 | §6 | 기본(75/90 가정, 출처 문구) |
| 11 | 대시보드 전체 시작 | `startAll.mutate()` 결과를 화면에 보이지 않음 | §2 [미결] | 전체 시작 일부 실패 |
| 12 | 대시보드 전체 중지 확인 | 개수만 안내하고 어느 채널인지 보이지 않음 | §1 | 전체 중지 확인 |
| 13 | 갱신 시각 | 목록, 대시보드 어디에도 "마지막 갱신" 없음 | §5 | 기본 |
| 14 | 연결 끊김 | 오류 알림 처리는 있으나 기존 데이터 유지 여부는 소스만으로 확인하지 못함 | §5 | 연결 끊김 |

잘 되어 있는 점(유지): 사용 중 파일 잠금과 이유 툴팁, 삭제 실패 시 대화상자 유지, 전체 중지 확인, 파일명이 남는 폭을 모두 쓰는 열 구성, 감소 모션 설정.

## 목업에서 새로 정한 것 (확인 필요)

- 입력 확인 문구는 `삭제`. 항목 이름이나 개수를 입력하게 할지는 미정입니다.
- 사용 중 파일이 선택에 섞이면 업로드까지 막습니다(현재 코드와 같음). 대신 "사용 중 항목만 선택 해제" 단추를 추가했습니다.
- 휴지통 "7일 보관"은 가짜 값입니다. 실제 값은 설정에서 가져와야 합니다.
- 갱신 주기 "5초"와 "마지막 갱신" 표시는 구현 확인 전의 가정입니다.
- 디스크 예측("N시간 분량 남음")은 계산 방식이 정해지지 않아 넣지 않았습니다.
- 좁은 화면에서는 파일명을 두 줄까지 보여주고 "사용 중" 배지를 다음 줄로 내렸습니다(PRODUCT.md "파일명이 가장 넓은 폭").

## 검증한 것

Playwright로 1440px, 390px, 어두움, 밝음을 열어 봤습니다. 가로 넘침 없음, 콘솔 오류는 favicon 404뿐입니다. 입력 확인 대화상자는 입력 전 비활성, `삭제` 입력 후 활성, 휴지통 전환 시 입력란 숨김까지 동작을 확인했습니다. 키보드 탐색과 스크린 리더 낭독은 확인하지 않았습니다.
