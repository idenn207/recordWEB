# 트랙 asr 실험 로그 (가창/가사/음성 기반 신호)

브랜치 `proto/sd-asr`, worktree `C:\_tools\wt\sd-asr`. 원시 결과는 `cache/proto_asr/` (전사 json `tx/<태그>/<gid>.json`, 표 출력 `results/*.txt`, 스템 `stem/`, 활동 캐시 `act/`).
언어/도구 선택: 전부 Python. 이유는 faster-whisper, torch(CUDA), torchaudio(MMS_FA), torchcrepe, silero-vad, demucs 가 모두 Python 이고 이 저장소의 song-detect 도구(snap, memo_audit, golden_gate)가 Python 이라 Go/TS 로 옮길 이득이 없다(병렬화 병목은 GPU 경합이지 언어가 아님).
GPU 는 5개 트랙이 같이 써서 처리 속도(rtf)가 단독 실행보다 약 2배 느리게 나왔다(small 단독 첫 실행 0.035, 경합 중 0.064). VRAM 열은 다른 트랙 프로세스가 섞여 부정확하다(모델 로드 직후 증가량: small 약 0.75GB, medium/large-v3 int8_float16 약 2.06GB).

## 0. 용어와 지표

- 창 = 곡 base 경계(메모 감사 기준, v3 시점) +-60초를 전사. 단어 타임스탬프는 방송 절대초.
- 가사 단어 = 환각 필터 통과 + 오디오 지지(YAMNet Singing>=0.15 또는 Music>=0.3, 그리고 Singing>=Speech).
- 끝 early 검증기(flag): 현재 끝 e 뒤 20초 안에서 e-3초 이후 가사 단어가 gap 8초 이내로 이어진 사슬이 3단어 이상. 시작 late 검증기는 거울상.
- 양성 = 메모가 early(끝)/late(시작)이라 한 곡, 음성 = 사용자가 "경계 좋음(ok)"이라 한 비 N 곡. 표 "tp/양성, fp/음성".
- 표본이 작아 전부 참고값이다. 임계(k=3, gap=8, W=20)는 처음 정한 값에서 거의 안 움직였지만 표본 내 값이다. 이진 비율의 95% 구간(Clopper-Pearson): 4/12 [0.10,0.65], 5/12 [0.15,0.72], 1/31 [0.00,0.17], 1/9 [0.00,0.48], 4/9 [0.14,0.79], 8/12 [0.35,0.90].
- 평가 기준 (1) golden gate 이탈 0: 이 트랙은 판정 코드(snap/route/make_final)를 바꾸지 않았으므로 기준선 그대로 통과(`results/golden_gate_baseline.txt`: golden 113곡 이탈 0, blind9 N 75행 등록부 없이 auto 0). (2) 메모 감사는 8절. (5) 등록부 없는 N 노출 14/55 기준선 대비는 10절.

## 2. 가사 경계 -> 곡 경계 변환 (축 a, 메모 숫자 정답)

가사 첫/끝 단어 시각은 곡 시작/끝보다 전주/후주만큼 안쪽이다. 사용자가 경계가 좋다고 한 곡에서 (가사 첫 단어 - 곡 시작): small 자동 중앙 31.4초 [IQR 23-83], multilingual 29.9초 [24-33], 가사 끝은 곡 끝보다 중앙 47.4초[107, 8] 앞(자동) 또는 26.6초[35,13](multi). large-v3+multilingual 은 가사 끝이 곡 끝보다 중앙 4.4초[-14,3] 앞이라 가장 정확하지만 고정 오프셋 LOO hit@3 는 시작 0~4/14(자동 7/36), 끝 0~3/9 이다. 즉 가사로 경계를 정하는 것은 hit@0.5 를 한 곡도 못 맞추고(0/36, 0/29), 경계 검증(플래그) 이상으로 쓸 수 없다. 이유는 전주/후주 길이가 곡마다 6~144초(10~90 분위)로 다르기 때문이다(shortcut: 이 오프셋 분포가 지금 얻을 수 있는 가장 정직한 상한).

## 11. 요약 판정

채택 후보(통합 후보):
1. `experiments/asr_bounds.py: propose()` 와 `n_asr.py` 는 연결 가능한 최소 형태로 두되 **자동 적용하지 않음**. B/review 카드 힌트(끝 뒤 가사 지속, 시작 앞 가사 존재)로만. 근거는 hold-out 끝 early 검증기 tp 3~5/10-12, fp 0~1/26-31.
2. Whisper 를 쓸 일이 생기면 `multilingual=True`, chunk 환각 필터는 쓰지 않고 세그먼트 반복 필터, `condition_on_previous_text=False`, `vad_filter=False`, 보컬 스템 사용 안 함, small 로 충분(medium/large 이득 없음).
3. 부산물: 점수 신호만의 끝 연장 사슬(musv, W60 gap15 min3)이 끝 early 12곡 중 8곡을 음성 2/31 로 잡는다([0.35,0.90]). 이는 ASR 이 아니라 snap.env_end(E1b) 쪽 보강 후보라 boundary 트랙에 넘긴다(미구현).

기각: 가사 경계로 곡 경계 제안(hit 개선 없음, 시작은 ok 곡 훼손), TAIL 대체(Whisper 1/7 대 YAMNet 7/7), 강제 정렬, 보컬 스템 전사, VAD 전사, 온도 폴백, 이전 문맥, 프롬프트, medium/large, 피치 기반 따라 부르기, ASR 기반 N 신호(라이브 손실 없이 추가 포착 0).

미결/한계: 모든 판정은 귀로 듣지 않은 점수/전사 기준. 숫자 정답이 있는 end-early 곡은 4곡뿐이고 #20/#26 은 정답이 창(+-60초) 밖이라 가사 사슬로는 볼 수 없다. 창을 150초 이상으로 늘린 실험은 안 했다. 가사 진위(환각 vs 진짜 가사)는 정답 가사가 없어 직접 측정하지 못했고 "단어/분", 환각 의심 비율, 검증기 정오로만 간접 비교했다.
