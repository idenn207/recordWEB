# sweep 트랙 실험 기록 (브랜치 proto/sd-sweep, 2026-10-29)

목표: 파라미터와 임계를 실측으로 탐색하고 민감도(응답 곡면), 현재 값의 최적 대비 거리, 과적합 위험 임계를 낸다. 코드 변경은 상수 변경만.
원시 결과는 `cache/proto_sweep/` (json, png, 로그), 전체 표는 `experiments_log/sweep_tables.md`(자동 생성). 아래 "그림"은 모두 직접 열어 보고 해석했다.

## 0. 쓰는 법 (다른 트랙용)

- **상수 오버라이드**: `tune.py`. 키 형식 `snap.LOW`(모듈 상수), `route.P.scene_ok`(딕셔너리 항목), `snap.deep_end.depth`(함수 기본 인자). `python tune.py list` 로 바꿀 수 있는 129개 이름과 현재 값.
  - 코드에서: `import tune; undo = tune.apply({...}); ...; undo()`
  - 환경변수: `SONG_TUNE='{"snap.E1B_LOUD":10}'` 또는 `SONG_TUNE=@파일.json` -> `import tune` 하는 순간 적용. `golden_gate.py`, `memo_audit.py`, `logo_route.py` 는 이 한 줄(`import tune`)을 넣어 두었으므로 환경변수만으로 전/후 비교가 된다(검증: `SONG_TUNE='{"snap.E1B_LOUD":9}' python experiments/memo_audit.py engine engine` -> hit@0.5 5 -> 6, 같은 값을 sweep_core 가 독립적으로 냄).
- **빠른 경계 평가기**: `experiments/sweep_core.py` `Evaluator(workers, wide).evaluate(cfg)` -> golden 이탈, 메모 hit/방향/좋음/길이, 전 방송 840구간 이동 수. cfg 는 tune 키 + `_off`(끌 규칙 목록) + `_order`(끝 규칙 순서). 1회 0.8~2.5초(원본 두 게이트 합 약 17초). 기준 재현을 selftest 로 확인(`python experiments/sweep_core.py selftest`).
- **route GPU 평가기**: `experiments/sweep_route.py`(`build`/`check`) 가 route.tier + mark_likely(weak) + n_signals.fire 를 후보 표 211행(라이브 136 + N 75, 등록부 없음) 위에서 torch 로 벡터화. `check` 가 원본 코드와 무작위 설정 300개를 대조(차이 0)하고 기본값 노출 14/55, 라이브 손실 0/136 을 재현.
- 주의(실수 기록): `logo_route.py eval` 은 기본 `--out` 이 공용 `data/review/blind9/audit/logo_route.json` 이다. 나는 `--golden --cands` 옵션으로 한 번 돌려 이 파일을 덮어썼고, P6 최종 로그(`cache/audit/logo_p6_final.txt`)와 출력이 같은 옵션(`eval --boot 1000`)으로 다시 돌려 복구했다(출력 diff 0, 파일 내용 cmp 동일). 이후 `--out cache/proto_sweep/...` 만 썼다.

## 1. 선택과 이유

- 언어/장치: 파이썬만 썼다(Go/TS 는 이득 없음: 병목이 numpy 와 torch 라 서비스화 이점이 없다).
- **GPU**: route/N 신호 탐색(분기가 조건식뿐인 표 연산)은 torch 로 벡터화해 설정 100만 개를 3초에 평가한다. **경계 규칙(snap/finalize)은 CPU 병렬**: 곡마다 조건 분기가 순차적이고 방송 pcm 을 읽는 구조라 GPU 이득이 없다. 대신 병목이던 `snap.rms_db`(전체 시간의 95%)를 벡터화하고(원본과 최대 0.01 dB 차이, 400개 무작위 구간 확인) 경계별 결과를 LRU 캐시해서 평가 1회를 7~10초에서 0.8~2.5초로 줄였다.
- 읽은 문헌(초록 수준, 읽지 않은 것은 인용 안 함): Optuna(Akiba 외 2019, arXiv 1907.10902) - 샘플러 TPE/CMA-ES/NSGA-II 는 Optuna 구현을 썼고 각 알고리즘 원 논문은 읽지 않았다. SAM(Foret 외, arXiv 2010.01412) - "주변이 고르게 낮은 손실" 아이디어를 차용해 이웃 교란 안정성 기반 선택(`robust`)을 만들었다(SAM 알고리즘 자체는 아님). Learn then Test(arXiv 2110.01052) - 위험 상한과 고정 순서 검정 아이디어만 차용. SALib 문서(Morris mu_star/sigma).

## 2. 가장 중요한 해석 주의: golden 이탈은 "정확도"가 아니라 "이동 폭"

`golden_v4.json` 은 현재 코드의 출력으로 동결했다. 그래서 기본값에서는 **정의상 이탈 0** 이고, 상수를 어느 쪽으로 움직이든 V 자로 이탈이 늘어난다(그림 `oat_*.png`). 이 지표가 말하는 것은 "승인 곡 경계가 2초 이상 움직이지 않는 허용 폭"이다. 정확도는 메모 숫자 정답(22곡-경계)과 방향 27, 경계 좋음 67 이 보지만 표본이 작다. 따라서 이 트랙은 "현재 값이 맞다"를 입증하지 않고 "어디까지 움직여도 승인 곡이 안 움직이는가, 어디가 절벽인가"를 잰다. detect 단계 평가도 같은 이유로 라벨이 기준 출력에서 나온 것이라 완화(느슨하게)하는 쪽의 이득은 구조적으로 안 보인다(7절).

## 5. 경계 규칙 상수: 민감도와 위험 목록

그림: `cache/proto_sweep/oat_1.png` ~ `oat_6.png`(각 상수의 golden 이탈=빨강, hit3 손실=파랑, 방향 손실=초록, 이동곡 수=점선). 전부 기본값(회색 점선)에서 최소가 되는 V 자라는 점이 2절의 이유다.

**한 번에 하나(OAT) 요약** (표 T1/T2):

- 죽은 상수: `snap.E1_SP`(0.05~0.6 전 범위에서 모든 지표와 840구간 결과가 동일). 거의 죽은 상수: `PAD_EDGE`, `E1_MIN`, `music_run.gap`, `E1B_CAP`, `CODA_FAR`(이동 5곡 이하). 제거/단순화 후보지만 새 데이터에서는 달라질 수 있어 변경하지 않음.
- 게이트 허용 폭이 가장 좁은 상수(첫 실패까지 거리, 2% 단위): `E1_GAP` 2%(아래, truth 포함), `E1B_MU` 2%(위, truth 포함), `E1_MU` 2%(위)/6%(아래, truth 포함: 그림 `grid2.png` 맨 아래: 0.85 열만 통과하는 섬), `start_s1.gap` 2%(위, truth 포함), `LEAD`/`LOOK`/`MU`/`start_s2.spmax` 2%(golden 이동만). 이들은 규칙이 표본 몇 건의 경계에 맞춰 있다는 뜻이다(주석의 "표본 3개 근거"와 일치).
- 넓은 고원: `snap.B_GAP`(3.2~4.8 이상 전부 통과, 하위 2.0 에서 실패), `E1B_GUARD`, `E1B_SP`, `E1_CAP`, `CODA_FAR`, `start_s1.min_left`, `start_s2.maxback`, `make_final.PAD_*`/`TAIL_*`(곡 경계 지표에는 안 보임).

- TPE 601시험(기본 +-6%, 약 40개 상수 동시): golden 이탈 0 은 163개, 그 중 점수(hit 합 + 방향)가 기준보다 높은 것 146개(방향 13 -> 15, hit 동일). 그러나 **이동 곡이 최소 26곡**(840구간의 3%)이라 `bsearch.png` 처럼 정답 점수를 올리는 모든 설정이 라벨 없는 곡 수십 개를 움직인다. 영향 범위가 작은(<=5곡) 개선 설정은 E1B_LOUD 류 1개뿐이다.
- 스트리머 hold-out(11명, 학습 = 그 스트리머 항목을 뺀 점수, 평가 = 뺀 항목): 점수 105 -> 107. 이득은 토아(방향 +1)와 나나(방향 +1)에서만, 나머지 9명은 변화 0, 악화 0. 방향 항목이 있는 스트리머가 6명이라 표본이 작다(`bsearch_holdout.log`).
- 동시 교란 안정성(E21): 경계 상수 약 40개를 동시에 기본값 +-1%/2%/4%/6%/10% 로 흔들면 golden 이탈 0 은 2/60, 1/60, 4/60, 0/60, 0/60 이고 이탈 곡 중앙값이 10~15.5 이다. 단독으로는 +-20% 를 견디는 상수가 25개인데 함께 움직이면 거의 항상 이탈한다 = 현재 상수 조합이 승인 곡 경계를 정확히 맞춘 한 점에 있다. 재중심화 설정에서는 +-1% 8/60, 2% 4/60, 4% 6/60(이탈 중앙 5, 6, 7.5)으로 소폭 개선.
- 이 지표는 "승인 곡이 움직이지 않는가"(2절)라 안정 영역이 좁다고 규칙이 틀렸다는 뜻은 아니다. 운영 지침: 상수는 한 번에 하나씩 바꿔 golden 으로 확인하고, 여러 개를 함께 바꾸면 곡이 움직일 가능성이 높다.
