# 통합 기록 (브랜치 proto/sd-integrate, 기준선 song-detect/baseline-20261029 = 8f841a3, 2026-10-29)

다섯 프로토타입(sd-sweep, sd-boundary, sd-visual, sd-harness, sd-asr)의 채택안을 기준선 위에 한 단계씩 별도 커밋으로 얹고, 단계마다 게이트를 돌려 전/후를 적었다. 원시 결과는 `cache/proto_integrate/`(메인 cache 의 하위 폴더), 도구는 `harness/`와 `experiments/integ_*.py`.
검수 한계: 모든 경계/화면 판단은 파형, 점수, 스펙트로그램, 프레임 이미지를 Read 로 직접 보고 했다. 귀로는 듣지 못했다(청취가 필요한 항목은 unverifiable).

## 0. 공통 표본과 정의 (모든 수치는 이 정의로 다시 적었다)

트랙마다 "N 노출 10/55", "14/55", "23/55" 가 서로 다른 것을 셌다. 아래로 고정한다.

표본
- N 55: blind9 사용자 N 판정 고유 곡 55개(`data/review/blind9/labels.json`). NAS 후보 191개 중 등록부 N 라벨 55개(known_negatives 의 blind9 항목)와 개수가 같다(곡 단위 대조는 안 함).
- 라이브 49: blind9 라이브 고유 곡 49개(신호 표 기준). NAS 후보 카드로는 라이브 61(blind9 47 + 재생목록 14)이 같은 범위를 덮는다.
- 승인 golden 113: `experiments/golden_v4.json`(이탈 게이트, 승인 라이브 경계/클립/등급).
- hold-out 라이브 풀 136: 신호 표 라이브 88 + 표에 없는 golden 라이브(`logo_route.py --golden`).

용어
- N 노출 = N 55 중 **등록부(known_negatives/approved) 없이** 사람에게 보이는 곡 수. 보임 = 등급 auto 이거나 weak 가 아닌 review/optional. (등록부를 켜면 55곡 전부 drop 이라 0 이고 이것은 규칙 성능이 아니다.)
- 라이브 손실 = 라이브 곡 중 drop 이거나 weak 인 수. golden 113 은 별도로 golden gate 가 경계/클립/등급 하락을 센다.
- 두 열로만 보고한다.
  - A(표본 내): 배포 임계 그대로. 임계가 이 표본에서 정해졌으므로 **회귀 감시용**이지 일반화 수치가 아니다. **A 의 머리 수치는 하나다: 배포 경로 vis(`out/<방송>/4_scene.json`, NAS 프레임 8장)까지 얹은 11/55.** `integ_holdout.py eval` 첫 표와 191카드 둘이 같은 값을 낸다. 같은 이름으로 따로 나오던 값은 입력이 다른 것이라 이름을 바꿔 병기한다: 오디오만 14/55(logo_route, `check.py` 상한 14), 프로토 프레임 12/55(visual 트랙 클립 프레임, 참고용: 같은 곡의 배포-프로토 vis 가 평균 +0.06, 표준편차 0.23, 범위 -0.59~+0.91 이라 임계 근처 몇 곡이 바뀐다). `check.py` 는 두 집합(오디오만 14곡, 배포 경로 11곡)을 저장본(`cache/harness/check_accepted/logo_sets.json`)과 곡 단위로 비교해 **새로 노출된 N 곡**과 라이브 손실(blind9 49, 라이브 풀 136)만 이탈로 세고 개수는 보고만 한다(개수 단언은 임계 근처 N 몇 곡 때문에 거짓 실패/개선을 낸다, 9.2절 A2-6).
  - B(hold-out): 스트리머 단위로 제외하고 신호 선택과 임계를 다시 정함(`logo_route` 행 D m=0.1), 라이브 풀 136, 그 위에 n_visual 임계도 스트리머 제외로 다시 정해 얹음. **일반화 주장은 B 로만 한다.** 표본이 스트리머 11명이라 구간이 넓다.
  - **B 의 n_visual 은 임계만 hold-out 이다.** 정규화(z 의 mu/sd), 프롬프트 5세트, 모델 선택(SigLIP2 B/16)은 표본 내다. 임계도 독립 증거가 못 된다: 폴드 11개 중 9개의 vis 임계가 1.017 로 같고(나머지는 히나 폴드 0.988, 나나 폴드 0.979) 표본 내 임계(배포 1.026)와 같은 곡이 정한다: 학습 라이브 최댓값이 시라유키 히나 144p 1곡(golden 15831370@1190, 0.789)이라 히나 말고는 어느 스트리머를 빼도 같은 곡이 임계를 정한다. 정규화까지 폴드마다 다시 맞춘 값은 `integ_holdout.py eval` 의 "정규화까지 재적합" 줄(프로토 프레임 표)이고 값은 4절에 병기한다.
  - 라이브 풀 136 의 golden 라이브 48행(신호 표에 없는 승인 곡)은 구조 규칙 입력(tstd, blk, scene, multi, struct_cls: 저장된 4_scene.json)과 점수 캐시 오디오 특징을 채워서 센다(`logo_route.with_golden`). 이전에는 오디오 신호 2개(rel_db, bursts)만 채워 이 48행이 구조 규칙과 나머지 후보 신호에 한 번도 시험되지 않은 채 0/136, 4/136, 5/136 으로 보고됐다(9.2절 A2-3). 화면 키프레임 특징 3개(moving_frac, bright_px, diff_med)는 이 48행에 없어 그 신호가 선택돼도 이 행들에는 적용되지 않는다(hold-out 손실은 하한).

표의 라이브 손실은 리뷰 A2-3 으로 정정한 값이다(이전 표는 1/49, 4/136). 이전에는 라이브 풀 136 의 golden 48행에 오디오 신호 2개만 채워서, 이 행들이 구조 규칙(tstd 움직임, struct_cls)과 나머지 후보 신호(speech_frac, sing_std 등)에 시험되지 않았고 폴드의 임계도 그 값 없이 정해졌다. 지금은 저장된 4_scene.json 의 입력과 점수 캐시 오디오 특징을 채워 blind9 행과 같은 규칙으로 센다(화면 키프레임 특징 3개만 비어 있어 손실은 하한). 같은 규칙의 배포 판(표본 내) 라이브 손실은 채워도 0/136 이다(48행 모두 구조 규칙을 통과, tstd 가 비어 있는 15761307 의 5곡 제외 모두 tstd 34.5 이하).
n_visual 이 더하는 손실: hold-out 임계 m=0.1 에서는 blind9 49 와 전체 136 모두 +0 이다. 그러나 m=0.0 에서는 전체 풀 136 에서 2 -> 3(+1)이 나온다(`integ_holdout.py eval`). m=0.1 은 이 표본에서 고른 값이므로 "모든 조건에서 0" 이라고 말할 수 없다(리뷰 A3에서 정정). 규칙 D 자체의 hold-out 라이브 손실은 blind9 0/49, 라이브 풀 2/136(blind5 V15 후야: 움직임 tstd 34.2 가 폴드 임계 초과, golden 15827672@17743: 마시로 폴드에서 bursts_per_min 1.95 가 임계 1.31 초과)이고 통합 전부터 있던 hold-out 특성이다. 배포 규칙(표본 내)의 0 손실을 일반화 수치로 읽으면 안 된다.
**n_visual 의 B 열은 독립 증거가 아니다**(리뷰 A2-1, A2-2): (1) hold-out 은 임계(학습 라이브 최댓값 + m x 범위)뿐이고 정규화(mu/sd)·프롬프트 5세트·모델 선택은 표본 내다. (2) 임계도 폴드 11개 중 9개가 1.017 로 같고 표본 내 임계(배포 1.026)와 같은 곡이 정한다: 학습 라이브 최댓값은 어느 폴드에서나 시라유키 히나 144p 1곡(golden 15831370@1190, 0.789)이고, 히나 폴드만 마시로 0.762 를 쓴다(0.988). 나나 폴드의 0.979 는 학습 최솟값이 올라 범위가 바뀐 것이다. 즉 폴드 임계는 사실상 표본 내 임계라서 "hold-out 에서도 줄었다"를 뒷받침하지 않는다. (3) 정규화까지 폴드마다 다시 맞춘 독립 추정(프로토 프레임, 성분 5개를 저장해 mu/sd 를 그 폴드의 학습 행으로 재적합)도 결과가 같다: m=0.1 에서 blind9 N 노출 14/55(규칙 D 16), 라이브 손실 0/49, 라이브 풀 2/136이고 m=0.0 에서는 10/55 로 재적합 안 한 값(11/55)보다 1곡 더 줄지만 이것도 같은 한 곡 임계 위의 값이다. 새 스트리머의 라이브가 임계를 넘는지는 이 표본으로 시험되지 않았다.

**이득의 크기를 말할 수 없다(스트리머 단위 부트스트랩 4000회, `experiments/integ_boot.py`)**: blind9 N 55곡은 스트리머 6명(리제 29, 나나 14, 히요리 8, 랑 2, 토아 1, 메리 1)이다. 규칙 D 대 D + n_visual 의 노출 감소 곡 수는 점추정 3곡(배포 경로: 리제 10-03 @13763, 나나 10-03 @23454, @23799. 이 중 나나 2곡은 같은 방송의 GTA 노래방)이고 95% 구간은 **[0, 7]곡(비율 [0.000, 0.121])로 0 을 포함한다**. 프로토 프레임 표에서는 2곡(나나 10-03 의 두 곡)이고 구간 [0, 6]. 스트리머별 이득은 나나 2 + 리제 1, 나머지 4명은 0 이다. 채택 근거는 "weak 표시만이라 손실 위험이 작다"로 한정하고, hold-out 에서도 줄인다는 문장은 쓰지 않는다.

- 일반화 근거는 boundary 트랙의 그룹 제외 평가뿐이다(boundary.md 5.2): S3 계열 9개만 고르면 +4 [0, +11], 98개 설정 풀에서 고르면 +0 [-5, +4]이고 이득은 16개 방송 그룹 중 2개(나나 10-16, 메리 10-18)에서만 나왔다. 이 구간들은 0 을 포함하므로 위 이득은 일반 개선으로 읽지 않는다. 회귀 감시(승인 곡이 안 움직임, 좋음 67/67 유지)와 "알려진 사례 4곡을 되찾음" 정도로만 주장한다.
- 일반화로 말할 수 있는 것: 시각 신호의 이득은 hold-out 으로 지지되지 않는다(리뷰 A2-1). 스트리머를 제외한 폴드에서도 N 3곡이 줄었지만 그 폴드의 vis 임계는 표본 내 임계와 같은 곡(히나 144p 1곡)이 정했고 정규화·프롬프트·모델 선택은 표본 내라 독립 증거가 아니며, 이득 구간은 [0, 7]곡으로 0 을 포함한다. 채택 근거는 "weak 표시만이라 손실 위험이 작다"와 표본 내 회귀 감시(알려진 라이브 246행 중 임계 초과 0)로 한정한다.

## 5. 추가 시도 (게이트 통과분만 채택, 기각도 기록)

### (a) 시각 점수로 review 정렬 -> 기각
- 방법: 등록부 끈 191후보에서 노출된 review/optional 68곡(N 7, L 43, B 18)을 vis 내림차순으로 정렬.
- 결과: 노출 안 N 7 vs 라이브 61 의 AUROC 0.789, 상위 10곡 중 N 2(무작위 기대 1.0), 상위 5곡 중 N 2. weak 표시가 vis 가 높은 N 을 이미 가져가서 남은 N 은 vis 가 낮아(0.0~0.57) 라이브와 섞인다. 등록부를 켠 실제 review 21곡은 B 18 + L 2 + U 1 이라 정렬로 얻을 것이 없다. 표본 N 7 개라 통계적 검정력도 없다.
- 채택 안 함. review.csv 우선순위는 기존(자체 검수 low/mid/high) 그대로.

### (b) 규칙 AND 학습형 weak (CRC alpha <= 0.05) -> 기각
- 방법: sd-harness 의 ranker(LR C=0.3, 18특징, 그룹 hold-out)에 vis 특징을 더해 규칙 D + vis 와 AND. CRC 임계는 학습 라이브의 안쪽 교차검증 p 에서 (k+1)/(n+1) <= alpha. 스트리머 hold-out, 신호 표 163행(라이브 풀 88).
- 결과(blind9 N 55 / 라이브 49): 규칙 D + vis 4/55 손실 0/49(전체 2/88). 여기에 LR(18특징, FULL) AND: alpha 0.05 -> N 3, **blind9 라이브 손실 1/49**, 전체 4/88. alpha 0.10 -> N 3, 손실 3/49, 전체 9/88. q0(학습 라이브 최솟값) -> N 3, 손실 0/49, 전체 3/88. 특징에 vis 를 더하면(FULL+vis): alpha 0.05 -> N 2, 손실 1/49, 전체 5/88 / alpha 0.10 -> N 1, 손실 2/49, 전체 9/88 / q0 -> N 2, 손실 0/49, 전체 2/88.
- 판정: CRC alpha <= 0.05 는 목표(손실 0)를 어기고, q0 는 N 4 -> 2~3 으로 1~2곡 줄이는데 표본 163행짜리 모델을 배포해야 하고 임계 표준편차가 15~50%다. 이득이 구간 안(55곡 중 1~2)이라 채택 안 함. 도구는 sd-harness 브랜치에 있다.

### (c) asr 가사 힌트(끝 뒤 가사 지속, 시작 앞 가사 존재)를 B/review 카드 힌트로 -> 연결 안 함(측정만)
- 방법: asr 트랙 전사 캐시(t_small_auto, 49곡)와 사슬 규칙(k=3, gap 8초, W 20초, 시험 전에 정한 값)을 **통합 트리 경계(engine_rev)** 에서 재측정. 양성 = 메모가 early/late 한 곡, 음성 = ok 로 판정한 곡.
- 결과: 끝 early tp 3/12, fp 1/31 (S3 영향 없음). 시작 late tp 4/9, fp 1/36(플래그 20, 50, 54, 144). 힌트로는 오탐이 낮다(3%).
- 판정: 연결하려면 호스트에 faster-whisper 와 후보당 약 20초 GPU 전사가 파이프라인에 들어간다. 근거는 양성이 끝 12곡, 시작 9곡뿐이고 구간이 넓다(asr 트랙 hold-out 구간 끝 [0.15, 0.72]). 63곡 중 힌트가 도움 될 곡은 서너 곡이라 비용 대비 이득이 작아 연결하지 않았다. 필요하면 `proto/sd-asr` 의 `experiments/asr_bounds.propose` 를 카드 힌트로만(auto 금지) 쓰면 된다.

### (d) YAMNet 추가 클래스(Rapping/Humming/Breathing 등) -> 기각
- 방법: 분석기 컨테이너(ai_edge_litert + GPU)에서 현재 시작 앞 40초~뒤 10초를 0.5초 간격으로 다시 점수화(9개 클래스), 시작 late 9곡 vs ok 36곡. (캐시에는 Singing/Speech/Music 3열만 있고 cache/proto_* 에 추가 클래스 점수는 없었다.)
- 결과: 시작 앞 20초 max/mean 의 단독 AUROC(late 이 큼): Humming 0.56~0.57, Breathing 0.23~0.37, Rapping 0.52~0.54, Whispering 0.38~0.50, Chant 0.56~0.60, Yodeling 0.65~0.76(중앙값은 late/ok 모두 0). 메모가 명시적으로 "허밍이 빠졌다"고 한 #65 의 시작 앞 20초 Humming 최대가 0.02, 전주가 짧게 빠진 #58 의 Breathing 최대 0.11.
- 판정: 놓친 전주/허밍/호흡을 YAMNet 클래스는 가리지 못한다(점수가 거의 0). 기각. 원자료 `cache/proto_integrate/yam_out.npz`.
