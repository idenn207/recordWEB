## 1. 방법

- 언어: 파이썬(기존 구조 재사용). Go/TS 는 쓰지 않았다. 이유: 입력이 0.5초 간격 점수 배열과 memmap pcm 이라 병렬/서비스화 이득이 없고, 기존 snap/finalize/golden/memo_audit 를 그대로 재사용해야 전/후가 같은 기준이다.
- GPU: SSM novelty 와 커널 합성곱은 torch(CUDA, venv `C:/_tools/wt/venv`)로 돌렸다. 나머지는 점수 배열이 작아(방송당 수만 행) GPU 이득이 없어 numpy. VRAM 사용 1GB 미만.
- 작업대(코드 비변경): `experiments/bound_lab.py`(finalize.snap 을 "원래 snap + 제안 규칙"으로 바꿔 메모 감사 + golden gate 를 한 번에 계산, 같은 입력 snap 결과 캐시로 설정당 약 10초), `bound_rules.py`(제안 규칙 팩토리), `bl_sweep.py`(전 방송 840구간 이동 목록 + 카드 등급), `bl_logo.py`(그룹 제외 선택), `bl_committee.py`, `bl_detsim.py`, `bl_endpolicy.py`, `bl_struct.py`, `bl_unres.py`.
- 정책 두 가지를 같이 측정했다. `all` = 제안 규칙을 모든 후보에 적용(golden 이탈이 그대로 드러남), `rev` = golden(승인 라이브/재생목록 정답) 후보는 건너뜀(= 승인 라이브 경계는 안 건드리고 B/review 후보에만). golden 이탈은 `진짜`(정답에서 멀어지거나 사유 없음)와 `정답쪽 개선`(재생목록 정답 시작에 1초 넘게 가까워진 이동)으로 나눠 센다.
- 지표: memo_audit(숫자 정답 13곡-경계 hit@0.5/3/10, 중앙 |오차|, 방향 27, 경계 좋음 유지 67, 길이 오차>5초), golden gate(113곡), 전 방송 sweep(후보 840개, 카드 등급별 이동 수).
- 기준선(규칙 변경 없음, 이 worktree 에서 재현): hit@0.5/3/10 = 5/9/11, 중앙 1.9초, 방향 13/27, 경계 좋음 67/67, 길이 오차>5초 2곡, 곡 사라짐 0, golden 이탈 0. `python experiments/golden_gate.py`, `python experiments/memo_audit.py` 로 나온 값과 일치.

## 3. 채택: S3 시작 제안 (코드 변경)

- `snap.start_s3(pcm, a, s, s0)`: s 앞 30초 안 마지막 깊은 무음(< -50dBFS, 0.5초 이상)의 끝을 제안 시작으로. 가드: S1 이 시작을 민 곡 제외, 사이 Speech>0.5 프레임 비율 >= 0.4 제외, 사이 (Singing+Music) 평균 < EXT_MU(0.25) 제외, 이동 1초 미만 제외. snap 의 시작 규칙 순서/trace 합계 assert 는 건드리지 않는다.
- `finalize.fix`: 제안이 있고 원래 후보 길이의 2.5배 안이면 `g["alt_start"]` 에만 기록(start 불변). `pipeline.card` 가 `boundary.alt_start` 로 카드에 남긴다.
- `make_final.make`: `tier != "auto"` 일 때만 제안 시작을 쓰고 stage `S3 start` 로 이동량을 기록한다(규칙 귀속 유지).
- 검증 도구: `audit_engine.calc(use_alt=)`, `memo_audit` 의 `engine_rev` 소스(= make_final 과 같은 정책), `golden_gate.current` 가 같은 정책으로 계산.

- 알려진 한계(shortcut 주석): #60(시작 OK 라고 한 곡)처럼 앞에 멘트/박수가 낀 곡을 거르는 값(EXT_MU)이 표본 1건 근거이고, 같은 값을 낮추면 #58 이 풀리지만 #60 이 깨진다(둘이 Music 0.01 로 구별 안 됨). RULE("v5-bounds")은 올리지 않았으므로 기존 완성본은 그대로고, 새 시작으로 review 클립을 만들려면 RULE 을 올리고 `reroute_nas.py` + `final_nas.py` 를 돌려야 한다(NAS 401 상태라 하지 않음, 공유 out 폴더도 건드리지 않음).

## 4. 끝 처리 정책 비교 (E05: 말소리 유입 vs 곡 꼬리)

대상 131곡(golden 113 + 메모 라이브). 곡 소리는 깎지 않는다(페이드는 곡 끝에서 시작해 컷에서 끝남). 유입 = [곡 끝, 컷) 안 Speech>0.15 이고 곡 중앙값-25dB 이상인 프레임. 들림 = 페이드(곡 끝에서 선형, 길이 min(L, 컷-끝))로 깎인 뒤에도 같은 기준을 넘는 프레임. 꼬리 손실 = 컷 뒤로 말 없이 이어지는 소리(최대 3초) + 페이드로 6dB 넘게 깎인 말 없는 꼬리 초. 전부 `bl_endpolicy.py`, 원자료 `cache/proto_boundary/endpolicy.json`.

| 정책 | 평균 컷-끝(초) | 말 유입 곡 / 초 | 페이드 후에도 들림 곡 / 초 (L=1.0) | 꼬리 손실 곡 / 초 (L=1.0) |
|---|---|---|---|---|
| 현재(TAIL 가드 + 컷 연장 3초) | 0.90 | 30 / 8.5 | 30 / 8.3 | 49 / 76.9 |
| 여유 컷만(TAIL 가드 없음) | 0.51 | 18 / 5.1 | 16 / 4.3 | 56 / 71.8 |
| 고정 곡 끝 +0.3 | 0.30 | 30 / 8.5 | 30 / 8.3 | 47 / 71.4 |
| 고정 곡 끝 +1.0 (v4) | 1.01 | 62 / 37.3 | 57 / 32.4 | 42 / 69.2 |
| 고정 곡 끝 +2.0 | 2.00 | 87 / 96.1 | 57 / 32.4 | 64 / 115.7 |
| 말 직전 컷, 최소 +0.0 | 0.83 | 0 / 0 | 0 / 0 | 37 / 65.9 |
| 말 직전 컷, 최소 +0.15 | 0.86 | 30 / 4.5 | 29 / 4.1 | 38 / 66.4 |
| 말 직전 컷, 최소 +0.5 | 0.97 | 45 / 14.9 | 43 / 13.9 | 49 / 75.3 |
| 현재 + 연장 상한 6초 | 0.98 | 30 / 8.5 | 30 / 8.3 | 49 / 84.3 |

- 고정 +1.0 에서 페이드 길이만 0.3초로 줄이면 들림이 30곡 8.3초로 내려가지만 꼬리 손실(깎인 꼬리 포함)이 55곡 89.5초로 커진다. 길이 1.0~1.5초 페이드는 말을 거의 못 가린다(57곡 32.4초). 계획서의 "컷 +1초 + 페이드" 원칙은 말 유입이 큰 쪽이다.
- 말 직전 컷의 유입 30곡 8.5초는 전부 곡 끝 0.3초 안에 말이 시작하는 곡이다. 최소 여유를 0 으로 내리면 유입은 0 이 되지만 컷이 곡 끝 0~0.3초 뒤라 페이드가 사실상 없고, 곡 끝 추정 오차(점수 창 0.5초)가 곡 마지막 음을 자를 위험이 생긴다. 호흡/전주는 스킬이라 포함한다는 사용자 요구와 곡 소리 보존 요구 때문에 규칙은 바꾸지 않았다(청취 A/B 필요). 연장 상한 6초는 유입이 그대로이고 손실 지표만 커진다(길어진 컷 안의 꼬리가 페이드로 깎인 초로 세어진다).

## 6. 반복해서 확인한 사실 (실패 포함)

- E1b/E3/S1/S2 중 하나라도 끄면 hit 가 내려간다(E06). 새 규칙은 이 규칙들이 만든 경계 위에서만 얹혔다.
- 점수만으로 못 가르는 쌍: #58(이득, 3.6초 전주)과 #60(손실, 3.4초 박수/멘트)은 Music 0.01 로 같고 Speech 만 0.05 대 0.24 다. #60 은 말 비율 가드(0.4)에 안 걸린다. 사이 말 비율 가드를 낮추면(0.2) 승인 곡이 깨진다(S05).
- 호흡(#52, 23035.5): 곡 시작 직전 깊은 무음 1.4초 앞에 -45~-52dB 호흡 0.5초가 있고 그 앞은 더 큰 말(-26dB)이라 "단발 저레벨" 정의가 안 맞는다. 12개 설정 모두 못 잡음.
- 기존 계획서 수치 불일치: E5 의 #63 +10.5초는 재현되지 않았다(방향 13 불변). `memo_audit.py selftest` 의 manual_agree 단언(13)은 이 worktree 기준선에서도 11 이라 실패한다(P2 의 의도된 개선 때문, 이번 변경과 무관, 미수정).
