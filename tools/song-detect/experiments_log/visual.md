# 트랙 visual 실험 로그 (등록부 없이 화면 의미로 N 가르기)

브랜치 proto/sd-visual, 코드 `experiments/visual/`, 배포 후보 `n_visual.py` + `n_visual_cal.json`, route 연결 `route.mark_likely`. 원시 결과 JSON/로그는 `cache/proto_visual/res_*.json|txt`.

## 설정과 지표 (모든 실험 공통)

- 표본: 곡 204개 = 라이브 133 + N 71. 출처 blind9 완성본 클립(104), blind5/6 검토 클립(52, 144p 영상), refs(사람이 검수한 위치 정답 + 승인, 나나 NAS ts와 마시로/후야 로컬 mp4, 라이브 50). blind7/8 5행과 오디오 전용 클립 2개(V07, V21)는 영상이 없어 제외. 곡마다 구간을 8등분한 중앙 시각의 프레임 8장(398x224)을 `cache/proto_visual/frames/`에 캐시.
- N 유형(blind9 사용자 판정, 태그): 같이보기(타 스트리머 라이브) 12, 커버/공연 같이보기 12, 자리비움 BGM 9, GTA 노래방 9, 리듬게임 9, 게임 OST 7, 대기 화면 5, 잡담 중 BGM 5, 따라 부르기 3, 같이 듣기 1.
- hold-out: 스트리머 단위(11명, 기본) 또는 스트리머 x 방송일(46그룹). 점수는 클수록 N. veto 임계 = 학습 그룹 라이브 점수 최댓값 + m x 범위(m=0, 0.1, 0.2). 보고 항목: AUROC(+그룹 부트스트랩 95% 구간), 임계 초과 N 수, 라이브 손실, 유형별, 배포 규칙(표본 내) 통과 N 15개(blind9 14) 중 거른 수("노출 N").
- 눈 검수: 접촉 시트(`cache/proto_visual/sheet_*.jpg`)로 유형별 프레임을 직접 보았다. 귀로 듣지는 못함.
- 쓰는 모델: CLIP ViT-B/32, ViT-L/14(openai), SigLIP ViT-B/16(webli), SigLIP2 ViT-B/16(webli), 전부 open_clip, GPU fp16. VRAM 최대 1.6GB(SigLIP2 B/16, L/14), 프레임당 4~9ms. 소형 VLM은 SmolVLM-500M(1.0GB).
- 읽은 원문: Tip-Adapter(arXiv 2207.09519)와 Cross-Modal Adaptation(arXiv 2301.06267)은 초록만 읽었다(수식 미확인: Tip-Adapter 캐시 가중식은 초록에 없어 우리 구현이 원문과 같다고 주장하지 않는다). SigLIP/SigLIP2 논문 본문은 읽지 않았고 인용하지 않는다(모델 가중치만 사용).

## 좋아진 것 / 나빠진 것

- 좋아진 것: 등록부 없이 게임/리듬게임/GTA 노래방/게임 OST/공연 영상은 스트리머를 모르는 상태에서 상당수 걸러진다(위 표). 오디오 신호와 합치면(V19 점수화) 스트리머 hold-out 에서 N 56/71 을 라이브 손실 0 으로 거른다(오디오만 43/71, 손실 1). 규칙 통과 후보 안에서는 시각 점수로 정렬하면 N 이 앞쪽에 몰린다(상위 10곡 중 8곡).
- 나빠진 것/한계: (1) 단독 veto 는 m=0 에서 라이브 1곡을 잃는다. 리제 10-03 #14648(GTA 노래방과 같은 장면의 라이브, 프레임을 직접 확인)과 마시로 마인크래프트 라이브(refs 10612 는 프레임 확인, 11483 은 점수만 확인)가 N 과 같은 화면이라 화면 신호로는 못 가른다. (2) 타 스트리머 라이브 같이보기(12곡)와 따라 부르기(3곡), 대기 화면(4곡), 아바타 클로즈업의 자리비움 BGM 은 라이브와 화면이 같다(눈으로 확인): 이 유형은 화면이 아니라 오디오(원곡 지문 등)로 가려야 한다. (3) 감독 학습(프로브, 적응, 캐시)은 같은 스트리머가 학습에 섞이는 분할에서만 좋고 스트리머를 빼면 제로샷보다 나쁘다. (4) 구조 특징과 소형 VLM 은 이득이 없다.

## 주의 (과대 주장 방지)

- 모델 선택(SigLIP2 단독)과 E_layout 세트는 표를 본 뒤/접촉 시트를 본 뒤 정했다(선택 편향). 선택 없는 4모델 앙상블이 정직한 하한이다(N 22/71 손실 0 at m=0.1). 임계 m=0.1 도 이 표본에서 정했다.
- 라이브가 스트리머 2명(마시로 27+, 토아 33, 나나 36)에 몰려 있어 새 스트리머 일반화는 구간이 넓다(AUROC 구간 [0.81, 0.96]).
- 점수 정규화(mu, sd)는 이 204곡 통계다(라벨 안 씀). 새 방송 분포에서 이동할 수 있다.
- 프롬프트 세트 5개는 유형 목록(HANDOFF 25절)을 보고 썼고 곡 점수를 보고 고치지 않았다. 예외: E_layout 은 유형별 접촉 시트를 본 뒤 작성.

## 비용

- 프레임 추출: 로컬 클립 곡당 8프레임 약 1초, NAS(HTTP) 곡당 약 4.8초(프레임당 0.6초)가 병목. 임베딩+점수 곡당 0.03초(SigLIP2 B/16, GPU), 모델 로딩 약 20초. VRAM 1.6GB 이하.
